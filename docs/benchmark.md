# Проверка распознавания на Raspberry Pi

> Исторический тест, выполненный до сужения требований. Сейчас приложение планируется только для английской речи и файлов до 10 минут. Русские результаты и экстраполяция на два часа ниже сохранены как данные эксперимента, а не актуальные требования. Замер на десятиминутной английской записи пока не выполнен.

## Результаты первичного теста

Все четыре прогона завершились успешно. Проверены совпадение текста в TXT/SRT/JSON, порядок сегментов и границы временных меток внутри аудио.

| large-v3-turbo | Язык | Аудио | Обработка | RTF | Пик RSS | Максимум температуры |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| F16 | Английский | 11 с | 43.39 с | 3.94 | 1800 MiB | 69.40 °C |
| F16 | Русский | 60 с | 136.44 с | 2.27 | 1899 MiB | 74.35 °C |
| Q5_0 | Английский | 11 с | 47.48 с | 4.32 | 792 MiB | 74.90 °C |
| Q5_0 | Русский | 60 с | 154.82 с | 2.58 | 889 MiB | 75.45 °C |

На русском фрагменте Q5_0 уменьшила пик RSS примерно на 53%, но была примерно на 13% медленнее. Каждый вариант запущен один раз; порядок F16 → Q5 означает разные начальные температуры и состояние кешей. Это наблюдение данного теста, а не универсальная характеристика квантизации.

Для следующего этапа оставляем F16 основным кандидатом: её пик памяти около 1.85 GiB помещается на проверенном стенде. Уменьшение модели здесь не дало выигрыша скорости.

Английские расшифровки F16 и Q5 совпали. В русском тексте обе модели выдали «ханем» вместо ожидаемого «фонем» в описании согласных; ожидаемый термин сверяли с [текстом озвученной статьи](https://ru.wikipedia.org/wiki/Русский_язык). В конце обрезанного фрагмента варианты также разошлись («вакансирования» / «Восточной»); этот участок нельзя оценивать без учёта обрезанной границы аудио. Полной ручной сверки с записью и измерения WER не выполнялось.

Линейная экстраполяция минутного русского теста даёт около **4 ч 33 мин для двух часов аудио с F16**, около **5 ч 10 мин с Q5**. Это ориентир, не обещание времени: более длинные фрагменты, речь, паузы, нагрев и другие процессы меняют результат. Двухчасовая запись не тестировалась.

Полные результаты сохранены на Raspberry в `~/stt-benchmark/results/` и локально в игнорируемой папке `artifacts/benchmark/`. Исходные измерения без текста записей находятся в [benchmark-results.json](benchmark-results.json).

## Стенд

- Raspberry Pi 5 Model B Rev 1.1, четыре ядра Cortex-A76, ARM64.
- ОС сообщает Debian 12 (bookworm); доступная системе RAM — 7.9 GiB.
- Рабочая папка на Raspberry: `~/stt-benchmark`.
- Установлены CMake, FFmpeg и GNU time с зависимостями через apt.
- `whisper.cpp`: `v1.9.5`, commit `d1be6fde11ac6e0407606b4e42fe72d34add8037`.
- Сборка Release, `GGML_NATIVE=ON`, `GGML_VULKAN=OFF`, CPU, четыре потока.
- Распознавание: явный язык, без перевода и VAD; beam size 5, best-of 5, flash attention включён по умолчанию в этой версии.

## Повторение замера

Из корня рабочей папки на Raspberry, где лежат `benchmark.py`, `whisper.cpp`, `models` и `samples`:

```bash
python3 benchmark.py \
  --model models/ggml-large-v3-turbo.bin \
  --audio samples/ru-60s.wav \
  --language ru \
  --name repeat-fp16-ru
```

Скрипт хранится в репозитории как `scripts/benchmark.py`. Для каждого запуска нужно новое имя: существующие результаты не перезаписываются.
Результаты: `results/<name>/metrics.json`, полный текст `transcript.txt`, субтитры `transcript.srt`, сегменты `transcript.json`, диагностические логи.
Предельное время одного запуска — 1800 секунд, затем процесс останавливается; это защитный лимит теста, не ограничение будущего приложения.

RTF = время работы / длительность аудио. RTF > 1 означает обработку медленнее воспроизведения.
Время включает загрузку модели и создание результатов. Пиковая RSS измеряется GNU time; это память процесса, а не всего сервера.
Температура считывается из sysfs каждые пять секунд, поэтому кратковременные пики могут не попасть в измерение.

## Доступ и конфиденциальность

`scripts/remote.py` запускает локальный shell-скрипт на Raspberry через SSH с параметрами из игнорируемого `.env`:

```bash
python3 scripts/remote.py path/to/check.sh
```

Для установки системных зависимостей поддерживается `--sudo`; пароль подаётся через stdin, для SSH — через askpass.
Нужен ранее проверенный ключ сервера в `known_hosts`; проверка ключа не отключается.
Формат `.env`: по одному `KEY=value` на строку, допускаются внешние одинарные/двойные кавычки; интерполяция shell и встроенные комментарии не поддерживаются.
Не использовать shell tracing (`set -x`). Не печатать переменные подключения или содержимое `.env`.

## Ограничения

Короткие прогоны проверяют работоспособность, примерную скорость и память. Они не подтверждают точность на лекциях, устойчивость на двухчасовой записи или отсутствие пропусков.
Для оценки качества нужны реальные английские и русские лекции и вручную проверенная расшифровка. Различия между F16 и Q5 сами по себе не являются метрикой ошибок относительно речи.
