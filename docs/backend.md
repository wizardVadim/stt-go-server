# Бэкенд MVP

Реализован Go HTTP-сервер с SQLite, локальным хранением, одним worker,
FFmpeg/ffprobe и отдельным процессом whisper-cli. Поддерживается английская речь,
длительность строго больше нуля и не более 600 секунд. Браузер опрашивает список;
серверных push-уведомлений нет. API описан в `api/openapi.yaml`.

## Запуск локально

Нужны Go согласно `stt-service/go.mod`, FFmpeg/ffprobe и whisper-cli v1.9.5.
Модель: проверенный ранее large-v3-turbo F16. Зависимость SQLite —
modernc.org/sqlite v1.39.1, CGO не нужен. Версии Go-зависимостей закреплены в go.mod/go.sum.
Для Raspberry ранее установлен FFmpeg 5.1.9; новая установка в рамках реализации
бэкенда не выполнялась.

Из корня проекта:

```sh
cd web
npm ci
npm run build
cd ../stt-service
STT_MODEL=/absolute/path/to/ggml-large-v3-turbo.bin \
STT_WHISPER=/absolute/path/to/whisper-cli \
go run ./cmd
```

По умолчанию сервер слушает `127.0.0.1:8080`. Открыть этот адрес в браузере.
Для доступа из локальной сети явно задать `STT_LISTEN=0.0.0.0:8080`.
Аутентификации в MVP нет: не публиковать этот интерфейс в открытый интернет.
Конфигурация читается из окружения; `.env` не исполняется и автоматически не загружается.
SSH-параметры серверу не нужны.

В режиме Vite dev прокси сохраняет исходный Host, чтобы same-origin проверка
POST/DELETE работала и при разработке. В production frontend обслуживает Go.

## Конфигурация

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| STT_LISTEN | 127.0.0.1:8080 | HTTP адрес |
| STT_DATA_DIR | ./data | Данные и временные загрузки |
| STT_DB_PATH | DATA_DIR/jobs.sqlite | SQLite |
| STT_MIGRATIONS_DIR | ../migrations | Каталог миграции |
| STT_WEB_DIR | ../web/dist | Сборка Vue |
| STT_FFPROBE | ffprobe | Проверка медиа |
| STT_FFMPEG | ffmpeg | Подготовка WAV |
| STT_WHISPER | whisper-cli | Распознавание |
| STT_MODEL | обязательно | Путь к модели |
| STT_THREADS | 4 | Потоки inference |
| STT_MAX_UPLOAD_BYTES | 524288000 | Максимальный размер файла |
| STT_MIN_FREE_BYTES | 1073741824 | Резерв свободного места |
| STT_PROCESS_TIMEOUT | 24h | Максимальное время задания |
| STT_RETENTION | 24h | Хранение после finished_at |
| STT_CLEANUP_INTERVAL | 24h | Интервал очистки |

Пути данных нормализуются относительно рабочего каталога. Временные файлы и
постоянные исходники находятся внутри DATA_DIR: они должны оставаться на одной
файловой системе для rename. Приложение требует Linux, целевая архитектура ARM64.

## Хранение и обработка

- `tmp/upload-*` — потоковые загрузки; одна загрузка записывается за раз.
- `jobs/<uuid>/source` — оригинал; имя пользователя не участвует в пути.
- `jobs/<uuid>/audio.wav` — PCM mono 16 kHz, 16-bit, удаляется после обработки.
- `jobs/<uuid>/whisper.json` — промежуточный вывод whisper-cli.
- `jobs/<uuid>/transcript.json` — весь текст и абсолютные таймкоды в секундах.

Multipart разбирается потоково. Требуется один file и language=en, порядок полей
любой. Задание создаётся только после чтения всего multipart и проверки ffprobe.
Ограничены размер файла и всего запроса, контролируется свободное место при записи.
При отказе временный файл удаляется. Перед INSERT исходник синхронизируется и
перемещается. Один INSERT — атомарная SQLite-транзакция; файловая система в неё
не входит. Ошибка записи компенсируется удалением файла, аварийные остатки убирает
очистка. Успешный ответ — 202 Job со статусом queued.

Worker: queued → preparing → transcribing → completed/failed/cancelled.
Записи обрабатываются целиком, без чанков и склейки. Whisper запускается с `-l en`,
без translate и VAD. Прогресс берётся из границ выведенных сегментов; до первого
сегмента он неизвестен (null), паузы не имитируются таймером. Это прогресс обработанной
части записи, а не оценка оставшегося времени. Готовность фиксируется только после
атомарного сохранения и синхронизации результата. Текст не выводится в логи.

Отмена ждёт остановки группы процессов. При остановке сервера активное задание
помечается failed/interrupted. После аварийного перезапуска preparing/transcribing
также становятся failed/interrupted; queued остаются в очереди. Повтор использует
тот же ID и исходник, сбрасывает ошибку, прогресс, finished_at и промежуточные файлы.
Внутрипроцессный mutex согласует completion/cancel/retry/delete. Файловая блокировка
не позволяет двум экземплярам использовать один DATA_DIR; не запускайте серверы с
разными DATA_DIR и одним STT_DB_PATH.

Удаление доступно только для конечных заданий. Удаляются все файлы, затем ставится
removed_at; запись и исходный статус остаются в SQLite. API скрывает такие задания,
результат возвращает 404, повтор — 409. Очистка запускается при старте и каждые сутки:
убирает конечные задания старше суток и старые бесхозные UUID-каталоги/загрузки.
Активные загрузки защищены от очистки. Сбой чтения БД не разрешает удаление файла.

## Миграции

При первом старте применяется `001_init.up.sql` и устанавливается user_version=1.
Уже вручную созданная таблица с текущими колонками принимается. Старая схема с
completed_at вместо finished_at/removed_at отклоняется: сначала сделайте резервную
копию и отдельную миграцию. Автоматического удаления или пересоздания старой БД нет.

## Raspberry Pi / systemd

```sh
cd stt-service
CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build -trimpath -o ../artifacts/stt-server ./cmd
```

Шаблоны: `deploy/stt-server.service`, `deploy/stt-server.env.example`.
На целевой машине нужны пользователь/группа stt, доступный ему каталог /var/lib/stt,
бинарник, migrations и web/dist в /opt/stt. Указать реальные пути к whisper-cli и
модели в /etc/stt-server.env; пользователь stt должен иметь право чтения модели и
исполнения binary. Для существующей модели в домашнем каталоге дополнительно
проверить права прохода по родительским каталогам. Unit ограничивает запись /var/lib/stt.
Права файла окружения — 0600. KillMode=control-group останавливает дочерние процессы.

Установка unit и запуск на Pi в этой задаче не выполнялись. ARM64-сборка сама по себе
не подтверждает развёртывание или производительность на Raspberry.

## Проверки

```sh
cd stt-service
go test ./...
go test -race ./...
go vet ./...
cd ../web
npm run build
```

Тесты используют настоящую временную SQLite и лёгкие исполняемые заглушки движка.
Проверяются границы длительности, ошибки медиа, размер/свободное место, сохранение,
очистка при ошибке БД, отмена, повтор, восстановление, soft deletion и HTTP multipart.
Если локально есть FFmpeg/ffprobe, отдельный тест создаёт синтетический тон и проверяет
настоящую подготовку аудио. Реальное распознавание моделью и качество на Pi требуют
отдельного прогона. Флаг en не определяет язык речи автоматически.
