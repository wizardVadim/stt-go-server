# Инструкции для работы над stt-go-server

## Цель и границы

- Локальное приложение для полной транскрипции аудио и видео с речью только на английском языке. Русская речь и смешанные языки не входят в поддерживаемый сценарий.
- Целевая машина: Raspberry Pi 5, по данным пользователя 16 GB RAM и Raspberry Pi OS. Адрес и SSH-пользователь задаются только в локальном `.env`.
- Проверка по SSH: Raspberry Pi 5 Model B Rev 1.1, ARM64, четыре ядра Cortex-A76, ОС сообщает Debian 12 (bookworm). ОС видит 7.9 GiB RAM, а не заявленные 16 GB; учитывать фактически доступную память, причина расхождения не установлена. До установки зависимостей на корневом разделе было свободно около 69 GB. Go и Node.js пока не установлены ассистентом.
- Для тестирования установлены FFmpeg 5.1.9, CMake 3.25.1 и GNU time; `whisper.cpp` v1.9.5 собран в `~/stt-benchmark/whisper.cpp`. Модель и тестовые результаты находятся в `~/stt-benchmark`; методика и результаты описываются в `docs/benchmark.md`.
- SSH-вход с паролем из локального `.env` проверен. Не запрашивать пароль или приватный ключ в чате. Бэкенд MVP и шаблон systemd unit реализованы локально; развёртывание и полный прогон бэкенда на Pi ещё не проверены. Наличие тестового whisper-cli не означает развёртывание бэкенда.
- Поддерживать записи длительностью не более 10 минут (600 секунд включительно). Более длинные файлы отклонять, не обрезать автоматически. Точность важнее скорости; обработка асинхронная.
- Возвращать весь распознанный текст на языке оригинала. Не заменять его переводом, пересказом или исправленным генеративной моделью текстом.
- Пользователь пишет Go-бэкенд; ассистент отвечает за структурированный фронтенд и помогает с архитектурой, интеграцией и развёртыванием по запросу.
- Ниже описаны требования; реализованный локальный бэкенд и ограничения проверок описаны в docs/backend.md.

## Технологии и структура

- Backend: Go, HTTP API, SQLite для заданий и метаданных, локальная файловая система для медиа и результатов.
- Распознавание: `whisper.cpp` отдельным процессом через `exec.CommandContext`, без shell-интерполяции. FFmpeg/ffprobe для проверки и подготовки медиа.
- Проверенный исходный вариант: `large-v3-turbo` F16 с явно заданным английским языком. Изменение требований само по себе не меняет установленную модель; выбор другой модели требует замера скорости и качества на английских лекциях. Исторические русские тесты в `docs/benchmark.md` не означают поддержку русского в приложении.
- Квантизацию выбирать после сравнения качества и времени, не считать её автоматически лучшим вариантом при 16 GB RAM.
- Frontend: Vue 3, TypeScript, Vite, Single File Components. Не собирать приложение в одном HTML-файле или одном огромном компоненте.
- Предлагаемая структура Go: `cmd/server`, `internal/httpapi`, `internal/jobs`, `internal/transcription`, `internal/media`, `internal/storage`, `internal/config`.
- Предлагаемая структура frontend: `web/src/components`, `web/src/views`, `web/src/composables`, `web/src/api`, `web/src/types`, `web/src/styles`.
- Контракт API хранить в `api/openapi.yaml`; эксплуатационные инструкции — в `docs/`, systemd unit — в `deploy/`.
- Не создавать пустые абстракции заранее. Vue-компоненты отвечают за интерфейс, API-клиент — за запросы, composables — за повторно используемое поведение.

## Обработка заданий

- Загрузка файла создаёт постоянное задание и возвращает его ID. Закрытие браузера не прерывает работу.
- Хранить состояния `queued`, `preparing`, `transcribing`, `completed`, `failed`, `cancelled` и понятную причину ошибки.
- На Pi по умолчанию одно активное задание распознавания. Число потоков inference настраивать и измерять.
- Потоково сохранять загрузку на диск; ограничивать размер, проверять свободное место, длительность и наличие аудиодорожки.
- На сервере проверять фактическую длительность медиа через ffprobe до постановки в очередь распознавания. Не доверять длительности, присланной браузером. Файлы дольше 600 секунд и файлы с неопределимой или некорректной длительностью отклонять с понятной ошибкой; очищать временную загрузку. Проверка в интерфейсе только вспомогательная.
- Подготавливать PCM WAV, mono, 16 kHz, 16-bit. Не загружать исходное видео целиком в RAM.
- При разбиении длинной записи сохранять абсолютные временные метки, небольшой перехлёст, порядок фрагментов и проверенные точки восстановления.
- При склейке удалять только подтверждённые дубликаты в перехлёсте, сохраняя намеренные повторы речи. Не терять начало и конец фрагментов.
- Язык распознавания фиксирован: `en`; режим — transcribe. Выбор языка и автоматическое определение в интерфейсе не нужны. Если API принимает параметр языка, разрешать только `en`. Флаг `-l en` не является проверкой фактического языка аудио: не обещать автоматическое обнаружение и отклонение иноязычной речи.
- VAD использовать осторожно, с запасом по границам речи и проверкой тихих участков. Не обещать отсутствие ошибок или галлюцинаций.
- Хранить полный текст и сегменты с временными метками. Экспорт: TXT, SRT, JSON.
- Для восстановления после перезапуска не оставлять задания навсегда в состоянии running; учитывать незавершённые процессы и готовые фрагменты.
- Прогресс показывать по реально обработанной длительности; не выдавать загрузку файла за прогресс распознавания.
- Отмена должна останавливать дочерние процессы. Удаление задания должно корректно очищать связанные файлы.

## Интерфейс

- Простой адаптивный интерфейс на русском: загрузка, список заданий, статус, просмотр полного текста, копирование и скачивание. У загрузки явно показывать «Только английская речь · до 10 минут»; убрать выбор языка.
- Различать прогресс загрузки, подготовку и распознавание. Показывать ошибки и возможность повторить задание.
- Текст отображать безопасно, без интерпретации HTML из результата.
- Восстанавливать отображение состояния после обновления страницы через API; не хранить единственную копию результата в браузере.
- Не добавлять перевод, суммаризацию, разделение по спикерам или запись микрофона без отдельной потребности.

## Эксплуатация и проверка

- Цель: Linux ARM64, запуск через systemd, frontend-сборка обслуживается Go с того же origin.
- Пути к моделям, данным, FFmpeg и whisper-cli, порт и лимиты задаются конфигурацией. Не зашивать IP Raspberry Pi в frontend.
- Фиксировать версии инструментов и моделей. Медиа, веса, секреты, SQLite и временные файлы не коммитить.
- Считать SSH-логин и адрес подключения конфиденциальными. Брать их из локального `.env` (`DEPLOY_SSH_HOST`, `DEPLOY_SSH_USER`, при необходимости `DEPLOY_SSH_PORT` и `DEPLOY_SSH_KEY_PATH`); не переносить значения в документацию, код, логи или ответы. Не выводить содержимое `.env` в инструментах. Не выполнять `.env` как shell-скрипт.
- `.env` и его локальные варианты должны игнорироваться Git; в `.env.example` хранить только имена параметров и несекретные значения по умолчанию. Не передавать параметры SSH во frontend и не использовать для них префикс `VITE_`. Приватные ключи и пароли не коммитить. Допускается пароль `DEPLOY_SSH_PASS` в локальном игнорируемом `.env`; не передавать его в аргументах команд, не выводить в логи и не копировать во временные файлы. Для локального `.env` использовать права доступа только владельцу.
- Не отправлять лекции внешним сервисам без запроса пользователя. Не писать содержимое лекций в обычные логи.
- Не утверждать, что развёртывание выполнено, пока сервис не проверен на целевой машине.
- Измерять время обработки, пиковую RAM и качество на репрезентативных английских фрагментах, включая термины, паузы и стыки.
- Не переносить GPU-бенчмарки на Pi. Для оценки десятиминутной записи использовать измеренный real-time factor с оговоркой о нагреве и различиях записей; короткий 11-секундный тест не считать достаточным замером для такого прогноза.
- Проверять существенные сценарии: повреждённое медиа, отсутствие аудио, нехватка места, отмена, перезапуск, склейка без потерь и экспорт полного текста.
- При реализации лимита длительности проверять значения меньше 600 секунд, ровно 600 секунд, больше 600 секунд и отсутствие корректной длительности. Не округлять превышение вниз для прохождения лимита.
- После изменений запускать соответствующие существующие проверки; когда проекты созданы — `go test ./...`, проверку типов и production build frontend.
- Общаться с пользователем по-русски. Явно различать реализованное, предложенное и ещё не проверенное.
